## 5. 技术架构评估

### 5.1 分层结构

项目整体采用较清晰的 Android Java 分层：

- UI 层：Activity、Fragment、Adapter、XML Layout
- 数据访问层：DAO
- 业务访问层：Repository
- 数据库层：SQLiteOpenHelper
- 后台能力：Foreground Service、BroadcastReceiver、AlarmManager
- 能力模块：ExportManager、BackupManager、WeeklyReportGenerator、DurationFormatter

这种结构适合课程设计答辩：既能说明 Android 原生组件，也能说明本地数据闭环和模块职责。

### 5.2 数据库设计

项目以 SQLite 为本地数据核心，覆盖：

- 分类
- 任务
- 标签
- 任务标签关联
- 专注记录
- 成就
- 倒数日
- 语录

数据库设计支撑了核心功能闭环，且没有为了 UI 改造随意新增字段，保持了结构稳定性。

### 5.3 工程规范

优点：

- 避免 Room、Compose、Kotlin、Firebase、Retrofit 等禁用技术。
- UI 已从大量程序化 View 迁移到 XML 布局。
- 主要页面已统一为 Premium Dashboard 风格。
- 字符串资源进一步集中到 `strings.xml`。
- 时长格式化已统一到 `DurationFormatter`。
- 导出、备份、恢复、设置已拆出独立管理类或 Repository。

仍可继续提升：

- 增加 Instrumented UI 自动化测试。
- 为恢复数据库流程增加独立测试环境和回滚测试。
- 对 Activity 中仍存在的少量 UI 聚合逻辑继续拆分。

## 9. 剩余风险与建议

| 优先级 | 风险或不足 | 建议 |
|---|---|---|
| 中 | 恢复数据库虽然已有校验和确认流程，但仍建议在独立测试数据上多轮覆盖验证 | 准备专门测试数据库，执行备份、损坏文件、错误文件、正常恢复用例 |
| 中 | 自动化测试覆盖不足 | 增加核心流程 Instrumented Test：创建分类、任务、专注、查看统计、导出周报 |
| 低 | 部分 Java 方法名保留英文 | 属于代码层命名，不影响用户体验；后续可在大重构时统一 |
| 低 | 深色模式目前固定开启 | 符合当前设计目标，后续 V3 可扩展主题切换 |
| 低 | GitHub 推送受本机代理影响 | 已确认可通过 Git 设置代理解决，不影响本地开发 |
